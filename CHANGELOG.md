# Changelog

All notable changes to Aegis-Seal are recorded here. Versions follow the
`Cargo.toml` version of the crate.

## [0.3.0]

- **Independent MACK vault checkpoint verification ("Twin Link").**
  `verify-checkpoint` reconstructs the vault's signed checkpoint message
  byte-for-byte (`"mack-checkpoint-v1"` ‖ seq as 8-byte big-endian ‖ head
  hash) and verifies the Ed25519 signature using only the four public
  values a checkpoint prints — no vault code, database, or signing key
  involved. A test vector generated by the vault's own signing code is
  pinned in `src/checkpoint.rs`, so any drift between the two
  implementations fails this crate's tests.
- Test count: 18 passing (scanner 5, crypto 4, ledger 4, checkpoint 5).

## [0.2.0]

- **Key custody hardening.** `keygen` writes the 32-byte seed to a key
  file (owner-only, 0600 on Unix) and refuses to overwrite an existing
  key. The v0.1 API that printed the private key as hex was removed
  entirely — the private key has no text export. The only key material
  ever displayed is the public key hex and its short fingerprint.

## [0.1.0]

- Initial release: Ed25519 signing and verification with memory-scrubbed
  keys (`zeroize`), streaming SHA-256 file hashing, constant-time digest
  comparison, the hash-chained append-only audit ledger, the
  secret-pattern and entropy scanner, and the CLI (`keygen`, `sign`,
  `verify`, `hash`, `scan`).

## Known limitations (stated plainly)

- **Not independently reviewed and not production-audited.** The README
  says so, and it remains true.
- **The ledger's hash chain is unkeyed.** It is tamper-evident, not
  tamper-proof: modification, deletion, or reordering of entries inside
  the chain is detected by `verify()`, but truncating entries from the
  tail leaves a shorter chain that still verifies, and a whole-chain
  rewrite recomputes cleanly. Anchor the chain tip somewhere outside the
  chain — signed checkpoints (see 0.3.0) exist for exactly that.
- **The scanner is heuristics, not a guarantee.** It rejects known
  credential patterns and high-entropy windows; it does not prove a file
  contains no secrets.
